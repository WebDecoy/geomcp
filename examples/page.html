Make product documentation easier to use

Good documentation helps readers answer a specific question without guessing which page to open next. Start with the task they are trying to finish, explain the prerequisites, and show the expected outcome before introducing optional details. Use accurate headings and real links so readers and automated clients can follow the same structure.

Start with the smallest complete example

A complete example includes the input, the action, and the result. Describe the failure cases as well as the successful path. Keep examples consistent with the current version and publish meaningful updates when behavior changes.
